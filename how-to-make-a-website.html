Selecting a Niche


Before making a website it is very important to have a purpose of the website – Why you have to make it?


Having a clear purpose helps you in building the website with clear elements and prevents messing up.


Many people fail because they can’t decide why they are making the website and end up frustrated, confused and give up – despite having knowledge and caliber to make one.


Don’t build ‘Just to build’ otherwise you will end up with the same question –

What do I want visitor to do here?


Also, don’t fall in ‘Jack of all trades’ problem – Making a website that covers too many themes it leads to stressing and burnout as you will end up with too many elements that have no outcome to serve.


Better strategy is to select one niche and let it unfold as you move further.


How I decided “The Niche”?


Well in my case I had a very clear niche and purpose – a simple portfolio website – where I can put my content, projects, codes, blogs, archives and many more.


And this helped me in building the website specifically for this purpose – having only the elements I need and avoiding messing up the code.


To do so I first went straight to web and searched the websites that specifically serve the purpose that I have to make a website for.


So, the tip for you is that instead of jumping in building – ‘Think’, ‘Wait’, and ‘Do some R&D’ - take a pen and paper, note down the elements, go on web look for the websites with exact elements that you noted down and then fire up the terminal.

Understanding Website Technologies


Before jumping to the building part you must know the technologies used to make a website. A website consists of three main technologies:


  1. Front-end: ”What the users see and interact with?” Ex. HTML, CSS, JavaScript

  2. Back-end: “What is running behind in the website? Ex. program, code, database

  3. Bridge: communication layer that connects both front-end and back-end


These three parts of a website together serve the purpose of what work a website does in a simple set of processes –


Front-end sends request – bridge carries it to back-end and – back-end fetches the

data and sends it to front-end – this process goes on.


Now let’s understand each of these technologies in detail:


1. Front-End: Client Side


Front is same thing that you are currently reading – it is what the website developer wants to show to its clients(users/readers).


It consists of menu, blogs, buttons, forms, animation etc. Readers can only interact with the front-end of a website.


There are three core technologies used to code the front-end:


  1. HTML: Structure of the webpage text, paragraph, title, images etc.

  2. CSS: Designs the webpage fonts, color, size, animation, responsiveness etc.

  3. JavaScript: Interactivity and behavior menu, slider, user interaction etc.


Visitors cannot directly see the back-end code, database, configurations or API keys.


Visitors only use the front-end, but the front-end constantly sends requests to back-end behind the scenes. Logging in, buying a product, reading blogs, posting a comment and many more.


Analogy:

Assume that website is a car so- HTML is the skeleton/chassis/frame of the car, CSS is the color, wrap and design on that chassis and JavaScript is the engine that runs the car.


Note: A website can be build using front-end only such as this one because it has no back-end server it is built using only HTML & CSS. I have explained this part in upcoming blog.


2. Back-end: Server Side


This is the part of website that does all the work behind the scenes, it runs on a server and is invisible to visitors.


Its job is to process user’s requests, manage databases, configure server, store and retrieve data and many more.

The commonly used back-end technologies are – Node.js, Django, Flask, Springboot, databases such as MySQL, PostregeSQL, MongoDB etc.


Unlike front-end technologies these don’t have specified purposes, rather they are used by every developer in there own way.


Analogy:

In this website there is only front-end so I can add new blogs for the visitors, customize the menu, make changes in font and color of the website, but with back-end I can create a log in panel, store comments from readers, keep visitor count and many more.


3. Bridge: Communication Layer


This part of website is responsible for the communication between both ends. It is not one technology but a combination of different bridge technologies such as:

  1. HTTPS: bridge between browser and server.

  2. Rest API: performs data exchange between both ends

  3. Fetch API: methods used by front-end to send requests

  4. Web Socket: real-time two way communication

  5. JSON: data format used in communication


The bridge is usually made up of – URLs, real-time HTTP requests(GET, POST, PUT, DELETE).


Bridge can be understood using Post-office Analogy:

You have to send a letter to your friend and post office is the medium used for that communication – let your house be front-end which is sending requests(letter) to your friend’s house(back-end) – and post office is the bridge which is working as a medium.


Front-end only site:

A front-end only website is made entirely by HTML, CSS, and JavaScript. It is also called a static website and its entire content, styling and logic is delivered and stored directly to user’s browser.


All three front-end technologies run entirely in browser thus there is no custom back-end server to process requests. But, the limitation is this type of site can’t process payments, store username, verify passwords or hide API keys.


Step-by-Step Process of building a websites


Now that you have understood the purpose, technologies and analogies about websites, lets start building and to do so we will move step-by-step beginning with front-end, than back-end and then bridging it.


Step-1: Designing Front-end


The first thing is to make a HTML template which will be the skeleton of the website. It consists of tags that contain the pages needed and typography of the webpage.


It is stored in a .html file which is the extension of any HTML code. It is a good practice to store the code in an index.html file for ease. Shown below is a basic HTMl template: 


<!DOCTYPE html> 
<html lang="en">
<head>
<meta charset="UTF-8"> 
<title>Page Title</title> 
</head>
<body> 
<h1>Main Heading</h1> 
<p>Paragraph text</p> 
</body>
</html>


In HTML there are tags that contain the content of the website it can be divided into two parts head and body:


<head></head> that contains information about the page such as title, metadata, style-sheet and script.


<body></body> that contains information visible to the users/visitors such as text, paragraph, headings, images, links, tables, etc.


After writing the HTML the next thing is to design the template which involves applying color scheme, styling and decorating each section individually.


To decorate a website we use CSS code and it is stored in a style.css file which contains all the designing instructions for the HTML template. Shown below is a basic CSS code: 


body {
    font-family: Arial, sans-serif;
    line-height: 1.6;
}
h1 {
    font-size: 2rem;
}
h2 {
    font-size: 1.5rem;
}
h3 {
    font-size: 1.25rem;
}
p {
    margin-bottom: 1rem;
}
hr {
    margin: 2rem 0;
}
code {
    font-family: monospace;
}


The CSS code can be added to HTML in 3 main methods:


  1. Inline CSS: written directly inside HTML tag using style keyword

    Example:

    <p style=”color:blue;”>Paragraph</p>

  2. Internal CSS: CSS is written inside <style> tag in <head></head> section

    Example:

    <head><style>p { color: blue ;}</style></head>

  3. External CSS: stored separately in a .css file and inserted using <link> tag

    Example:

    <head><link rel="stylesheet" href="style.css"></head>


Out of these 3 methods External CSS is the standard and recommended method as it allows to manages the CSS file separately and prevents error.


Once the template and design of website is ready then the JavaScript comes into play. JavaScript is a programming language that makes a website interactive and dynamic.


Shown below is a basic JavaScript code: 


function greet() {
    alert("Welcome to the website!");
}
function changeTitle() {
    document.querySelector("h1").innerHTML = "Title Updated";
}
function changeBackground() {
    document.body.style.backgroundColor = "lightgray";
}
function showDate() {
    alert(new Date().toLocaleDateString());
}

It adds features such as menus, animations, form validation and dynamic content. It can be in HTML and CSS by 3 methods:


  1. Inline JavaScript: written directly inside HTML elements

Example:

<button onclick="alert('Hello!')">Click Me</button>

  1. Internal JavaScript: written inside <script></script> tag in HTML file

Example:

<script>alert("Hello World!");</script>

  1. External JavaScript: stored separately in a .js file and inserted using <script></script> tag

Example:

<script src="script.js"></script>


External JavaScript is the standard and recommended method for making websites because a separate file makes the code organized, easier to update and makes it reusable.


Once the HTML, CSS and JavaScript is done – the front-end is completed then website is ready to be deployed if its front-end only or a static website and the back-end work can be done after that.


Some famous front-end only sites are – berkshirehathaway.com, paulgraham.com, c-faq.com.


Step-2: Building Back-end


The back-end is required only when a website needs server-side operations such as storing data, handling users, managing user accounts processing requests and configuring server.


Shown below is a basic back-end code in different back-end technologies such as Node.js, Flask and Java.


Node.js:(Express)


const express = require("express");
const app = express();
app.get("/", (req, res) => {
    res.send("Hello from Backend!"); });
app.listen(3000, () => {
    console.log("Server running on port 3000");});


Flask:(Python)


from flask import Flask
app = Flask(__name__)
@app.route("/")
def home():
    return "Hello from Python Backend!"

if __name__ == "__main__":
    app.run(debug=True)

Java:(Spring Boot)


import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
@RestController
public class HelloController { 
        @GetMapping("/")
           public String home() {
           return "Hello from Java Backend!"; 
       }
}


Other than programming languages back-end development also uses database technologies to store user’s data. Some commonly used databases are MySQL, MongoDB, PostgreSQL, SQLite, Firebase and Oracle.


Step-3: Bridge both the ends


When both front-end and back-end are made then API is needed to make both the ends communicate with each other. The front-end sends requests and back-end returns data in JSON format.


Commonly used bridge technologies are – Rest API, Fetch API, Ajax, Axios, Websockets and GraphQL. A basic bridge flow is shown below:

There are some terminologies used in bridging technologies listed below:

  • API: Application Programming Interface – allows both ends to talk

  • HTTP: HyperText Transfer Protocol – used to transfer data on webs

  • JSON: JavaScript Object Notation – a lightweight format used to send and receive data

  • REST: Representational State Transfer – a way of designing API using HTTP

  • AJAX: Asynchronous JavaScript and XML – send/receive data without reloading

  • URL: Uniform Resource Locator – address of web resources


After this step website is ready to be hosted and it will perform the purpose it is made for.


Step-4: Getting a Domain and Hosting


To make a website live a domain and a hosting platform is required so that anyone can access it using their web browser.


Domain means name of the website also known as website’s address – it often ends with .com, .in, .me, .io, .net, .org, etc. It is what users type in browser.


It can be either bought or rented annually from popular domain registers such as GoDaddy, Cloudfare, Namecheap, and Squarepace.


Hosting means a space or server that stores all the HTML, CSS and JavaScript online so that everyone can access it. Some common hosting platforms are GitHub, AWS, Netlify and Bluehost.


Step-5: SEO and Aftermath


SEO stands for Search Engine Optimization – it is the process of improving website’s visibility on Search Engines. Basic SEO factors are – Good Titles, Meta description, Properly placed Headings(h1, h2, h3), Fast loading website and Keywords in content.


Once the website becomes live and gets a host then it can be accessed by anyone from any part of world.


Whenever anyone searches the content related to it and to make the website appear on top of SERP(Search Engine Result Page) the SEO plays a big role.


Aftermath is what happens after the website goes live. Basic aftermath factors include – Indexing, Google Rankings, Traffic monitoring, Improvements and Updates made regularly. It plays a big role in maintaining the website.
